# Laravel Module — Requests

Form Requests handle input validation and authorization. They are the **only** place where incoming HTTP data is validated.

## Location

```
app/Modules/{ModuleName}/Requests/
├── Create{ModuleName}Request.php
├── Update{ModuleName}Request.php
└── UpdateStatus{ModuleName}Request.php
```

## Rules

1. Always extend `Illuminate\Foundation\Http\FormRequest`.
2. Always define `authorize()` — it **must** enforce the action's permission via `hasPermission()` (see [Authorization](#authorization)). Never leave it as `return true` on a module mutation.
3. Always define `rules()` with all required validation.
4. Optionally define `messages()` for custom error messages in Spanish.
5. Never access request data directly in controllers — use `$request->validated()` or typed accessors.
6. Use array-style validation rules (not string-style).

## Create{ModuleName}Request

The `id` field is **always required** in Create requests. The UUID is generated by the client (frontend) and sent in the request body — never generated on the backend.

```php
<?php

namespace App\Modules\{ModuleName}\Requests;

use Illuminate\Foundation\Http\FormRequest;

class Create{ModuleName}Request extends FormRequest
{
    public function authorize(): bool
    {
        return $this->user()?->hasPermission('{module}.create') ?? false;
    }

    /** @return array<string, array<int, mixed>> */
    public function rules(): array
    {
        return [
            'id'     => ['required', 'uuid'],
            'name'   => ['required', 'string', 'max:255'],
            'status' => ['sometimes', 'string', 'in:active,inactive'],
        ];
    }

    /** @return array<string, string> */
    public function messages(): array
    {
        return [
            'id.required'   => 'El identificador es obligatorio.',
            'id.uuid'        => 'El identificador debe ser un UUID válido.',
            'name.required' => 'El nombre es obligatorio.',
            'name.max'      => 'El nombre no puede superar los 255 caracteres.',
        ];
    }
}
```

```php

    public function authorize(): bool
    {

    {
        return [
            'name' => ['required', 'string', 'max:255'],
        ];
    }

    /** @return array<string, string> */
    public function messages(): array
    {
        return [
            'name.required' => 'El nombre es obligatorio.',
        ];
    }
}
```

```php
<?php

namespace App\Modules\{ModuleName}\Requests;

class UpdateStatus{ModuleName}Request extends FormRequest
{
    public function authorize(): bool
    {
        return $this->user()?->hasPermission('{module}.update-status') ?? false;
    }

    /** @return array<string, array<int, mixed>> */
    public function rules(): array
    {
        return [
            'status' => ['required', 'string', 'in:active,inactive'],
        ];
    }

    /** @return array<string, string> */
    public function messages(): array
    {
        return [
            'status.required' => 'El estado es obligatorio.',
            'status.in'       => 'El estado debe ser active o inactive.',
        ];
    }
}
```

## Authorization

This project does **not** use Gates/Policies for module CRUD. Authorization is permission-string based: a role (resolved per company) holds **action strings** of the form `{module}.{action}`, checked with `App\Modules\User\Models\User::hasPermission()`. A role with `permission_type = 'all'` (e.g. `Administrador`) passes every check.

Each mutation Request authorizes its own action:

| Request | Permission action |
|---|---|
| `Create{ModuleName}Request` (POST store) | `{module}.create` |
| `Update{ModuleName}Request` (PUT update) | `{module}.update` |
| `UpdateStatus{ModuleName}Request` (PUT status) | `{module}.update-status` |

```php
public function authorize(): bool
{
    return $this->user()?->hasPermission('{module}.create') ?? false;
}
```

- `{module}` is the plural, lowercase slug used in routes (`users`, `roles`, `companies`) — the same prefix used by the matching `GetController` checks and the sidebar menu.
- The null-safe `?? false` matters: an unauthenticated request (`$this->user()` is `null`) must be denied, not crash.
- A failed `authorize()` throws `AuthorizationException` → `403`. On Inertia requests a global handler in `bootstrap/app.php` turns that into a redirect-back with a flash `error` (shown as a toast), so **do not** add custom messaging here.
- The GET views for the same actions are guarded in the `GetController` (see the `laravel-module-controllers` skill); keep both sides in sync.

## Accessing Validated Data

In `fromRequest()` on the Command, always use typed accessors:

```php
// ✅ Correct
$request->string('name')->toString()
$request->integer('limit')
$request->boolean('active')

// ❌ Avoid
$request->input('name')
$request->name
```
